# Multi Agent v2 실행 검증

실제 collaboration 런타임에서 리더와 두 담당 에이전트가 스킬을 읽고 CSV 금액 합계 도구를 구현·검증했다.

## 환경과 산출물

- 스킬: `skills/multi-agent-v2/SKILL.md`
- 격리 작업 폴더: `examples/csv-totals/` (원본은 격리 임시 폴더에서 실행 후 이동)
- 구현: `/root/implementation`, `totals.py` 소유
- 계약 및 독립 테스트: `/root/contract`, `contract.md`, `test_totals.py` 소유
- 각 담당자에게 생성 응답의 실제 정규 경로를 전달했다. 리더는 API 계약이나 테스트 결과를 중계하지 않았다.

## 관찰 결과

1. 검증 담당이 동료에게 직접 API, CLI, JSON과 오류 처리를 질문했다. 두 담당자가 직접 계약 합의를 리더에게 각각 보고했다.
2. 구현 담당이 구현 완료 후 동료에게 직접 검증을 요청했다. 검증 담당이 9개 테스트 결과를 직접 회신했고 구현 담당이 수신을 확인했다.
3. 담당 파일의 소유권을 분리했으며 서로의 파일을 수정했다고 보고한 사례는 없었다.
4. 리더가 테스트 코드와 구현을 읽고 전체 테스트를 다시 실행했다. `Ran 9 tests in 0.376s`, `OK`, 종료 코드 0.
5. 구현 담당의 FINAL_ANSWER 수신 후 `followup_task`로 없는 파일 CLI 검증을 배정했다. 에이전트가 재개되어 종료 코드 2, 빈 stdout, 파일 없음 stderr를 보고하고 동료에게 직접 공유했다.
6. 원래 실패했던 스킬 파일 읽기와 샌드박스 안 임시 파일 생성·삭제가 성공했다. 스킬 형식 검증도 `Skill is valid!`로 통과했다.

## 재현 명령

```bash
python3 -m unittest discover -s examples/csv-totals -p 'test_*.py' -v
```

검증 항목: 정상 합계, 빈 금액, 0.1+0.2, 긴 소수의 정확한 합계, 헤더만 있는 입력, 잘못된 금액의 행 번호, 비유한 값 거부, 빈 파일 및 헤더 누락, 함수와 CLI.

## 범위와 한계

이번 샘플에서 직접 소통, 계약 합의, 공유 산출물, 독립 검증과 완료 에이전트 재개가 동작했다. 메시지 내용 요약은 담당자 보고와 `contract.md`에 기반하며 원본 런타임 전체 대화 덤프를 별도로 저장하지 않았다. 자동 스킬 검색, 다른 런타임, 충돌 복구, 장애 재배정과 대규모 작업은 시험하지 않았다. 스킬 소스 수정이 필요한 실패는 발견되지 않았다. 프로그램과 테스트를 examples/csv-totals에 보존했다. 직접 메시지 요약은 examples/csv-totals/contract.md에 보존했다.
