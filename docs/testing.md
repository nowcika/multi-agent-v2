# 테스트와 협업 재현

## A. 예제 프로그램 실행

저장소 루트에서 실행합니다. Codex 없이도 Python 표준 라이브러리로 동작합니다.

```bash
python3 examples/csv-totals/totals.py examples/csv-totals/sample.csv
python3 -m unittest discover -s examples/csv-totals -p 'test_*.py' -v
```

샘플의 합계는 `{"total": "10.55"}`입니다. 독립 테스트 9개는 정상 합계, 빈 금액, 소수 정확도, 긴 숫자, 헤더만 있는 입력, 오류 행 번호, 비유한 값 거부, 빈 파일·헤더 누락, API·CLI를 확인합니다. GitHub Actions도 이 프로그램 테스트를 실행하며 에이전트를 생성하지 않습니다.

## B. 실제 에이전트 협업 재현

스킬을 설치한 Codex에서 아래 요청을 입력합니다. 완성된 예제를 복사하는 시험과 구분하기 위해 별도의 새 폴더에서 구현합니다.

```text
$multi-agent-v2를 사용해 실제 협업 테스트를 해 줘.

쓰기 가능한 임시 폴더를 만들고 CSV 금액 합계 CLI를 새로 구현해 줘.
Python 표준 라이브러리만 사용하고 입력 헤더는 amount로 해 줘.
Decimal로 정확하게 합산하고 빈 금액은 건너뛰어 줘.
잘못된 금액은 실제 CSV 줄 번호를 stderr에 출력하고 exit 2로 종료해 줘.
성공하면 JSON을 출력해 줘.

리더와 담당 에이전트 2명으로 진행해 줘.
- 구현 담당: totals.py 소유
- 계약·검증 담당: contract.md와 test_totals.py 소유

담당자끼리 함수 API, JSON 형식과 오류 처리를 직접 협의해 줘.
동료의 실제 식별자를 알려 주고 리더는 메시지를 중계하지 말아 줘.
두 담당자 모두 이 스킬을 읽도록 해 줘.
계약·검증 담당은 직접 협의 요약을 contract.md에 기록하고
독립 테스트를 실행한 뒤 구현 담당에게 결과를 직접 전달해 줘.
리더도 결과물을 확인하고 전체 테스트를 재실행해 줘.
완성된 저장소 예제를 복사하지 말고 새로 작성해 줘.
```

기대하는 관찰은 다음과 같습니다.

1. 실제 담당 에이전트 2명이 생성됩니다.
2. 담당자가 동료에게 계약 질문을 보내고 회신을 받습니다.
3. 각자 맡은 파일만 수정합니다.
4. 구현 완료와 테스트 결과가 담당자 사이에서 직접 전달됩니다.
5. 리더가 테스트를 다시 실행하고 산출물 경로와 결과를 보고합니다.

에이전트가 답변에서 “소통했다”고만 말하는 것으로 끝내지 말고, 클라이언트에서 볼 수 있는 도구 호출과 에이전트 활동, 산출물 및 테스트 결과를 함께 확인하세요. 원본 메시지가 보이지 않는 환경에서는 그 제한을 결과에 기록합니다.

## C. 완료된 에이전트 재개

B가 완료된 같은 세션에서 요청합니다.

```text
방금 완료된 구현 담당에게 followup_task로 후속 검증을 맡겨 줘.
없는 CSV 파일 경로로 CLI를 실행하고 exit code, stdout, stderr를 보고하게 해 줘.
파일 수정은 필요 없어. 결과는 동료와 리더에게 직접 공유해 줘.
완료한 동료의 회신은 기다리지 않아도 돼.
```

기대 결과는 작업 재개, exit 2, 빈 stdout, 파일 없음 stderr입니다.

## 검증 범위

최초 실행에서는 직접 계약 합의, 결과 공유, 독립 테스트 9개, 리더 재실행과 완료 에이전트 재개가 성공했습니다. [실행 보고서](../reports/multi-agent-v2-test.md)를 참고하세요. 예제 테스트 통과만으로 모든 협업 동작이 검증되지는 않으며 자동 스킬 선택·대규모 팀·장애 복구는 별도 시험이 필요합니다.
