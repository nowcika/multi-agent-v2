# Multi Agent v2

사용자의 업무를 끝까지 수행하되, 담당 에이전트가 서로 직접 질문하고 의존 관계를 조율하는 것을 기본으로 한다. 리더에게 모든 메시지를 중계시키지 않는다.

## 실행 환경 확인

- 현재 노출된 도구의 실제 계약을 확인한다. 이 스킬에서 v2는 아래 협업 방식을 뜻하며, 특정 제품 버전이나 기능 플래그를 보장하지 않는다.
- `collaboration`의 `spawn_agent`, `send_message`, `followup_task`, `list_agents`, `wait_agent`가 제공되면 이를 사용한다. 협업 도구는 직접 호출하며 `functions.exec` 내부에서 호출하지 않는다.
- 직접 메시지를 보낼 도구가 없으면 제한을 알리고 가능한 독립 작업을 진행한다. 직접 소통이 되는 것처럼 보고하거나 임의의 설정 키를 만들지 않는다.
- 스킬 사용은 업무 범위와 실행 권한을 확대하지 않는다. 사용자와 상위 지침이 허용한 범위에서 위임한다.

## 팀 구성과 담당 배정

업무의 의존 관계를 보고 필요한 최소 인원으로 시작한다. 현재 슬롯 한도를 확인하고 리더도 한 슬롯을 사용한다는 점을 반영한다. 구현·조사·검증 등 실제로 분리할 가치가 있는 책임을 배정한다. 작은 업무는 불필요한 인원을 만들지 않고 그 이유를 설명한다.

각 담당자에게 다음을 전달한다.

- 전체 목표와 본인의 산출물, 완료 조건.
- 작업 경로, 수정할 파일의 소유권, 검증 방법.
- 다른 담당자와의 의존 관계 및 직접 협의할 주제.
- 관련 제약과 기존 사용자 변경 사항.

생성 응답의 실제 에이전트 식별자를 기록한다. 팀이 구성되면 각 담당자에게 동료의 **정규 경로 또는 실제 식별자**와 책임을 전달한다. 서로 다른 부모 아래의 동명 에이전트는 정규 경로로 구분한다. 아직 생성되지 않은 주소를 추측해서 전달하지 않는다.

자식 에이전트도 같은 협업 규칙을 따르게 한다. 추가 위임은 맡은 범위, 허용된 동시 실행 수와 비용 안에서만 한다. 기본적으로 리더가 인원을 관리한다.

## 직접 소통 규칙

담당자는 다음 상황에서 관련 동료에게 직접 `send_message`를 보낸다.

- 작업에 필요한 사실이나 인터페이스를 확인해야 할 때.
- 동료의 작업에 영향을 주는 발견, 변경, 실패를 알릴 때.
- 산출물을 인계하거나 검토·검증을 요청할 때.

메시지에는 목적, 근거 또는 파일 경로, 요청 사항을 짧고 구체적으로 쓴다. 예:

```text
[질문] /root/api 담당자에게: 로그인 응답의 expires_at 타입을 확인해 주세요.
근거: ui/session.ts에서 만료 시각 비교가 필요합니다.
요청: ISO 문자열인지 epoch 초인지 알려 주세요. 저는 그동안 화면 레이아웃을 진행합니다.
```

단순한 상태 방송과 형식적인 대화를 만들지 않는다. 질문을 받은 담당자는 답변 또는 확인에 필요한 조건을 회신한다. 합의가 영향을 주는 다른 담당자에게도 확정 내용을 공유한다.

`send_message`는 쉬고 있는 에이전트의 새 턴을 시작하지 않는다. 이미 완료했거나 대기 중인 동료의 추가 작업이 필요하면 리더에게 알린다. 리더는 `followup_task`로 해당 담당자에게 구체적인 후속 작업을 배정한다. 실제 도구가 허용하는 대상 범위 안에서만 사용한다.

대답을 기다리는 동안 독립 작업을 진행한다. 선행 조건이 해결되지 않은 부분은 추측으로 확정하지 않는다. 의존 관계가 순환하거나 필요한 상대가 응답할 수 없으면 리더에게 막힌 조건과 선택지를 전달한다. 리더는 담당 변경, 작업 순서 조정 또는 필요한 사용자 질문으로 해소한다.

리더에게는 범위·일정에 영향을 주는 장애, 결정된 공통 계약, 파일 소유권 변경, 최종 산출물을 보고한다. 사소한 대화를 모두 중계하지 않는다.

## 공동 작업 충돌 방지

공유 작업 공간에서는 에이전트의 변경이 즉시 보인다. 같은 파일의 동시 수정은 피하고 파일별 담당을 정한다. 공통 파일 변경이 필요하면 담당자와 수정 범위 또는 소유권 이전을 합의한다. 다른 담당자의 변경을 덮어쓰거나 되돌리지 않는다.

별도 작업 트리를 사용할 경우 실제 경로, 브랜치와 통합 담당자를 명시한다. 별도 작업 트리의 변경이 자동으로 공유된다고 가정하지 않는다. 공유 산출물과 인터페이스 변경에는 경로와 버전 또는 커밋을 함께 전달한다.

에이전트는 자신의 검증 범위를 명확히 기록한다. 동료 작업의 완료가 필요한 통합 검증은 선행 조건이 갖춰진 뒤 수행한다.

## 통합과 종료

담당자는 완료 전에 관련 동료에게 필요한 산출물을 인계하고, 리더에게 변경 내용·경로·검증 결과·남은 문제를 전달한다. 메시지 전달 자체를 작업 완료의 증거로 간주하지 않는다.

리더는 다음을 확인해 업무를 마무리한다.

- 담당자 간 계약과 실제 산출물이 일치하는지 확인한다.
- 발견된 문제는 담당자에게 구체적인 후속 작업으로 돌려보낸다.
- 전체 변경을 검토하고 업무에 맞는 통합 검증을 수행한다.
- 요청한 결과물과 검증 결과, 남은 제약을 사용자에게 보고한다.

새 사용자 지시는 영향받는 담당자에게 신속히 전달한다. 목표가 바뀌어 쓸모없어진 작업은 중단하거나 재배정한다. 기다릴 때는 런타임의 대기 도구를 사용하며 반복 상태 조회로 바쁘게 돌지 않는다.
